# V2.3 AI Advisor release notes

## Scope

- Website portfolio screenshots use a small CSS zoom and pan on fine-pointer hover. Touch and reduced-motion users see static images. Dense workflow and case-study diagrams and application brand marks stay static so labels and marks remain readable.
- The chat launcher loads the advisor interface only when opened. `/api/chat` is isolated from contact and news routes. The contact link opens the existing validated form with a category and intent, without a transcript in the URL or an automatic submission.

## Model setup before activation

The chat endpoint is unavailable unless all of these Worker bindings are present:

| Binding | Type | Purpose |
| --- | --- | --- |
| `AI_PROVIDER` | Worker variable | Set to `openai` to enable the implemented provider adapter. |
| `AI_MODEL` | Worker variable | An account-enabled Responses API model ID selected and verified by the operator. |
| `AI_MAX_OUTPUT_TOKENS` | Optional Worker variable | Output token budget, 100–400; default 400. Values above 400 are capped. |
| `AI_PROVIDER_KEY` | Worker secret | Provider API credential. Never place it in source, public Vite variables, or CI logs. |
| `CHAT_LIMITER` | Rate limit binding | Already declared in `wrangler.jsonc`, namespace `1002`, 8 requests per 60 seconds per client IP. |

The existing `SITE_ORIGIN` binding must match the public browser origin exactly. Stage and verify the new variables, secret, model access, and binding through Cloudflare's controlled version workflow before any traffic cutover. This branch does not configure a real credential, merge, deploy, or alter DNS, domains, email routing, or scheduled news refresh.

## Controls and data handling

- Requests require the configured origin, JSON, a Cloudflare client IP, and the rate limit binding. The server reads at most 12 KB, validates alternating roles and text length, and allows at most 12 user turns and 6,000 conversation characters. The UI enforces the same session limits. Provider output is capped at 400 tokens and 4,000 response characters; upstream requests time out after 14 seconds.
- Rate limiting is per Cloudflare location and approximate. Monitor aggregate usage and provider spend; set provider-side budget alerts before activating public traffic. An anonymous visitor can start a new local session, so the per-IP limit and provider budget are essential additional controls.
- Prompts use approved site data only. User input is treated as untrusted; no tools, external browsing, code execution, or privileged data access are enabled. The model can still err, so the UI discloses that answers need verification.
- Chat messages remain in React memory for the active tab and are sent to the model provider with `store: false`. The Worker does not persist transcripts, automatically send them through Brevo, or log message text, IPs, or credentials. Aggregate token counts and provider error status are logged. Provider-side processing and retention are governed by the selected provider's account terms and must be reviewed before activation.
- The contact form remains the only inquiry submission path. Visitors provide their own details and consent there; Turnstile, validation, rate limiting, and Brevo acceptance remain unchanged. The advisor does not claim delivery.

## Validation and release gate

Run `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, and `npm run worker:check`. Inspect desktop, mobile, touch and reduced-motion behavior. Before enabling production, verify the live provider account/model and secret in a non-production Worker version, exercise rate and cost limits, review the provider data terms, and approve the controlled deployment separately.

The repository has no model credential or selected model. Automated tests exercise the provider contract with mocked responses; no live model answer or production inquiry was sent. The local preview uses the production Turnstile site key, which does not validate on `127.0.0.1`; contact delivery remains covered by its existing automated tests and requires its normal production verification before release.
